# 学习版 v3：试用与 ERP 部署

版本入口：`/v3/`。原生产入口 `/` 和旧测试入口 `/v2/` 保持独立。原结果区、播放、统计、Excel / 图片 / PDF 导出继续复用；人工摆放在独立的“调整柜内摆放”页面进行。

## 先在 GitHub Pages 测试

1. 导入装箱单，进入“叠箱组合”。可以一键组合、手动拖动和输入位置；组合保存后整组落柜底，外部物品不进入其占地上方。
2. 回到排柜页计算，点“调整柜内摆放”。支持整组移动、允许方向旋转、换柜、暂存、撤销、锁定位置和重排未锁定部分。锁定上箱时同时锁定下方支撑。
3. 点“保存调整并去排柜”，原结果区展示调整后的方案，再点“确认最终方案”。理由可空着；普通操作没有理由弹窗。
4. “历史与学习”查看确认版本、原方案与最终方案的差异，补充实装或到货反馈。照片可选。
5. 新箱单中的相同包装可复用历史组合，仍重新检查现行规则。需要修改全公司默认偏好时，由负责人在“学习管理”分析、发布；可切回已发布旧版本。

Pages 是静态托管，本机模式将项目、调整、确认历史放在当前浏览器的 IndexedDB；清理浏览器会删除这些数据，不会自动共享到同事电脑。经验归档包含文字与布局，不包含照片。测试示例会标记为练习，保留记录但不参与正式学习。请用真实箱单测试实际学习效果。

## 学习的内容与边界

- 不依赖大模型或 GPU。第一层从确认版本提取可复用组合，按包装名称/编码、包装版本、尺寸、重量和箱型规则精确匹配，拒绝不兼容模板。
- 第二层在相同输入和约束下对比系统原始推荐与人工最终结果，使用低位摆放、同类相邻、组合占比三个透明特征给候选排序。先比较装入箱数、柜数，再比较偏好；不会为经验分数少装货。
- 同一 ERP 项目或由历史派生的方案按同一项目族计数，不靠复制或重复确认增加独立样本。原样采纳没有人工偏好差异，不计入偏好训练；输入变更后不强行配对。
- 至少 4 个独立项目的有效偏好对，才尝试训练与留出验证；不足时可先发布组合模板。留出集一致率低于 50% 的偏好版本不可发布。这个指标是人工偏好倾向的一致率，不是运输安全率，也不是装柜最优率。
- 承压、禁压、方向、支撑、柜门、柜型载重、组装完整性等硬约束继续由统一规则检查。不会从习惯推断承压能力，也不会学习放宽禁转规则。允许上压重量未知时仍提示生产确认。
- 确认、已实装、到货完好分开记录；未反馈不是完好。出现移位或货损的案例停止参与新推荐，受影响的已发布偏好暂退回模板模式，等待负责人重新分析。
- 共享模式的偏好原始推荐必须来自服务端保存的计算任务。只导入最终布局的历史用于案例与模板，不伪造修改前结果。

当前属于可解释的案例复用与偏好排序，不含运输动力学、绑扎强度计算、设备搬运路径仿真；现场固定措施与到货照片可附在反馈中。旧确认版本不会被后来发布的新规则改写。

## 本地运行服务

需要 Node.js 24，首次执行 `npm ci`。Node 进程同时提供 `/v3/` 静态页面和 `/api/load-planner` API。开发凭证模式必须显式开启：

```sh
PLANNER_AUTH_MODE=development \
PLANNER_DEV_TOKEN=replace-with-a-temporary-test-token \
PLANNER_SQLITE_PATH=./data/planner.sqlite \
npm start
```

打开 `http://127.0.0.1:8787/v3/` → 历史与学习 → 连接设置，服务地址填 `http://127.0.0.1:8787/api/load-planner`，凭证填临时测试值。开发模式返回测试负责人身份，仅用于本机联调。正式环境使用 ERP 验证，勿把这个模式作为公司登录。

未设置 `DATABASE_URL` 时使用 SQLite，便于单实例试用；正式共享建议用 PostgreSQL。照片放在 `PLANNER_ATTACHMENTS_DIR`，默认 `data/attachments`。服务默认只监听 `127.0.0.1:8787`，不直接开放数据库端口。

## 在 ERP 服务器旁部署

此仓库提供独立服务，不会修改 ERP 表、项目状态或业务接口。ERP 主机的真实登录协议、域名和权限配置尚需由运维接入，代码上传 Git 不等于已经部署到 ERP。

```sh
cp .env.example .env
# 修改 .env 中数据库口令、ERP 身份接口、允许的页面来源
docker compose up -d --build
curl http://127.0.0.1:8787/api/load-planner/health
```

Compose 为排柜系统建立单独 PostgreSQL 数据库与持久卷。数据库口令在连接网址中使用，因此示例要求生成足够长的 URL 安全文字（字母、数字、`-`、`_`）。如果复用现有 PostgreSQL，单独创建数据库和专用用户，通过 `DATABASE_URL` 运行 Node 服务；不要用 ERP 超级用户。

建议单实例 1 vCPU、768 MB 内存起步。计算在独立 worker 中串行运行，单任务默认 60 秒、worker 堆内存 256 MB，最多 30 个待执行/运行任务，每人最多 3 个。调整这些参数前用公司的大箱单实测。本版本没有针对大规模并发调优。

通过 ERP 现有 HTTPS 反向代理转发 API，示例 Nginx：

```nginx
location /api/load-planner/ {
    proxy_pass http://127.0.0.1:8787;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_read_timeout 75s;
    client_max_body_size 12m;
}
location /load-planner/ {
    proxy_pass http://127.0.0.1:8787;
    proxy_set_header Host $host;
}
```

前端也可以继续放在 Pages，通过连接设置访问 HTTPS API；将其实际来源加入 `PLANNER_ALLOWED_ORIGINS`，逗号分隔，按来源精确匹配。ERP 内嵌同源页面可以用下面的会话交接，地址必须使用真实服务域名：

```js
iframe.contentWindow.postMessage({
  type: 'planner:auth',
  api: 'https://erp.example.com/api/load-planner',
  token: verifiedSessionToken
}, 'https://erp.example.com');
```

只有同源父窗口的交接会被接收。凭证保存在当前标签页 `sessionStorage`，不会进入网址、经验归档或 Git。API 不信任前端传来的用户姓名、角色、项目权限。

## ERP 身份接口契约

配置 `PLANNER_AUTH_MODE=erp` 和 `ERP_AUTH_URL`。排柜服务将客户端 bearer token 转给这个 HTTPS 身份接口，ERP 必须验证登录、停用状态、角色与项目范围，然后返回 JSON：

```json
{
  "id": "employee-123",
  "name": "生产排柜员",
  "active": true,
  "roles": ["planner"],
  "projectIds": ["erp-project-001", "erp-project-002"],
  "allProjects": false
}
```

未登录返回 401，无权访问返回 403；不能直接转发客户端提供的权限。身份结果最多缓存 5 秒。项目未关联 ERP 编号时仅创建者和管理员可访问；关联后以 ERP 项目权限为准。负责人能分析公司经验与发布匿名模板，因此应只给实际生产规则负责人分配此权限。

| 角色 | 权限 |
| --- | --- |
| `viewer` | 查看授权项目、提交该项目的现场/到货反馈 |
| `planner` | 上述权限，加编辑项目、计算、确认和取消任务 |
| `policy_manager` | 排柜编辑，加分析、发布、回退、停用案例 |
| `admin` | 全项目管理及规则负责人权限 |

原始案例只返回有项目权限的用户；负责人发布的公司模板去除来源项目与人员字段后才跨项目共享。包装名称和包装尺寸属于模板内容，使用前应确认适合公司内部共享。若需限制部门或客户之间的知识流转，应分别部署实例；当前实现为单公司实例，不是多租户服务。

## 保存、冲突与任务恢复

每次成功草稿修订及柜内保存保留独立快照；确认案例不可覆盖，反馈、案例停用、发布和回退为独立记录。服务端比较修订号，两人编辑同一版本时后保存者收到冲突，不能静默覆盖。遇到冲突可从项目列表重新打开共享版本；要保留本机分支，可先导出项目，再作为新方案打开。

本机先保存有效编辑，后台同步草稿及有效操作。确认时若断网，先进入待同步队列，不提示为共享成功；回网后在历史页点“同步当前项目”。冲突待同步记录需要处理版本后重新确认。保存请求有操作编号，网络重试不重复生成确认样本。拖动过程的悬停帧不作为有效摆放；单次输入会话最多保留最近 500 个有效动作，确认前后快照完整保留。

后台排柜任务持久保存排队、运行、完成、取消、失败或过期状态，记录输入修订与租约。进程重启后重新领取过期租约，最多尝试 3 次；取消任务不写入新结果。输入修订已改变时旧结果标为过期，不覆盖新输入。

## 备份与升级

备份 PostgreSQL、照片卷和部署 `.env`；它们不在 Git 中。先验证备份能恢复，再更换服务镜像。示例：

```sh
docker compose exec -T planner-db pg_dump -U load_planner -d load_planner > planner-backup.sql
docker compose cp planner:/app/data/attachments ./planner-attachments-backup
```

SQLite 试用请停止服务后连同 `data/` 一并备份，不只复制运行中的主数据库文件。程序自动建立版本 1 数据表，当前没有破坏性升级脚本。回退经验版本使用学习管理中的“切换到此版本”；回退应用代码前保留数据库备份。健康检查路径 `/api/load-planner/health` 只说明服务可响应，正式上线还须检查 ERP 登录、授权项目访问、备份恢复和实际箱单。
